### 3.9 동일 데이터 재시작 대조 — 데이터를 바꾸지 않아도 저하되는가 (2026-09-08~09) — **이 조건에서는 저하가 관측되지 않았다**

상세: `<work-dir>/runs/C1-JSUT-RESTART-2026-09-08.md`. **2,000 step 짧은 런 1개**(≈10분). S2-inherit이 한 번에 바꾼 두 가지 중
**대상 데이터 변경만 제거**했다 — 같은 base export, 같은 `--posterior-init inherit`, 같은 스케줄로 **JSUT 데이터에** 다시 적응한다.
`--dataset` 한 개만 다르며 코드 시대도 같다. 묻는 것은 "**대상 데이터를 바꾸지 않아도 재시작·추가 학습 조건에서 출력이 나빠지는가**"
하나이고, **재시작 자체를 독립 원인으로 분리하지 않는다**(재시작과 그 뒤 2,000 step이 한 묶음).

무결성은 범용 검사의 임계가 아니라 **엄격 검사**(`<work-dir>/scripts/exact_match.py`)로 잡았고 전부 통과했다: 두 `training-options.json`이
**모든 키·값 일치**, `prepared_dataset` 3개 sha가 대상 데이터셋과 일치하며 baseline과는 전부 다름, base 체크포인트 sha 동일, 계승 리포트
3항(`sidecar`·100텐서·`verified_equal_after_copy`), **@500 추론 40/40 비트 동일**(warm-up 동안 추론 경로가 lr 0 + `requires_grad_(False)`이므로
성립해야 하는 등식), 손실 2,000행 전부 유한.

계기(서술): 같은 JSUT 텍스트 40문장에서 이 런의 추론은 2,000 step 내내 콤 초과 **+1 dB 대**·f0 **220 Hz**·잠김 **0~1/40**에 머물고,

계기 선호가 청취로 이어지지 않은 사례가 여러 번, 미잠김이 말소리가 아니었던 반례가 두 번 있었다. **판정은 청취로만 한다.**

**청취 판정 (2026-09-09)** — `listening/restart-jsut-20260908/`, JSUT 화자·JSUT 텍스트, **처음 쓰는 문장 0012·0031**, 9클립,

### 3.10 라운드 E — flow 복원 재확인, 새 문장 2개 (2026-09-09) — **다시 미결(+1, +2) · flow 축 반복 청취 종료**

상세: `<work-dir>/runs/S2-INHERIT-2026-09-06.md`(라운드 E 절). 페이지 2에서 `flow←500`의 이득은 원본 점수로 +2·+2로 기준에 도달했으나
`adapted2k` 복제쌍이 **1 대 2**로 갈려 분류가 바뀌었고, 그래서 미결이었다. 설계가 아니라 **복제쌍 하나의 1등급 불일치**에 걸린 미결이므로 같은 렌더
조건에서 **문장만 바꿔 한 번 더** 듣는다. **사용자 결정: 재확인은 한 번뿐이며, 다시 미결이면 반복 청취를 멈추고 데이터 전환 조건 분해로 넘어간다.
이번 결과만으로 장기 학습이나 모듈 동결을 선택하지 않는다.**

  **이번 미결은 catch에 걸린 것이 아니다** — 복제쌍이 두 문장에서 **세 축 모두 정확히 일치**(불일치 0단계)했고 복제 점수로 계산해도 이득이

- `adapted2k`가 두 문장 모두 1이므로 **미시험이 아니다** — flow 축을 시험했고 결과가 미결이다. `flowback`은 두 문장 모두 자연성 ≥ 2이지만

  모듈 귀속은 미결로 남기며, **flow 갱신 제한 학습 대조는 지금 선택하지 않는다**(기여 확인 분기 불성립). 장기 학습·모듈 동결도 선택하지 않는다.

**모듈 귀속은 미결 그대로이고 flow는 우선 검토 후보로 유지한다** — 페이지 2에서 flow 복원은 두 문장 모두 자연성 3·일본어 "예"였다.

### 3.11 라운드 F — 친숙한 JSUT를 화자 A 규모로 줄여 재시작 (2026-09-09) — **축소해도 큰 저하가 관측되지 않았다**

상세: `<work-dir>/runs/F1-JSUT-SMALL-2026-09-09.md`. 라운드 E에서 flow 복원이 다시 미결이어서 **flow 축의 반복 청취를 끝내고**
데이터 전환 조건 분해로 넘어왔다. 첫 후보가 이 대조다 — 전체 JSUT에서 품질이 유지된 **C1이 비교군으로 이미 있고**, 같은 화자·언어·계승
posterior를 유지한 채 규모만 화자 A에 맞출 수 있다. **2,000 step 짧은 런 1개.**

**질문은 "데이터량만이 원인인가"가 아니다** — step을 고정하면 자료량과 함께 같은 자료를 다시 보는 횟수, 부분집합 구성이 함께 바뀐다
(`max_steps`는 step 기준, 당시 `training.py`의 학습 루프). 그래서 묻는 것은 "**친숙한 JSUT도 적은 자료를 반복 학습하면 저하되는가**"이고
**"자료량이 원인"이라고 쓰지 않는다.**

| arm | 자료 | 통과 수 |
|---|---|---|
| C1 | 전체 JSUT 6,959행 / 8.901 h | 2.3 (epoch 3) |
| S2-inherit | 화자 A 1,170행 / 1.519 h | 13.7 (epoch 14) |
| **R1**(이 런) | **축소 JSUT 1,170행 / 1.508 h** | **13.7 (epoch 14)** |

부분집합은 `<work-dir>/scripts/make_subset.py`로 만들었다: `prepared/ja-jsut-v1`을 복사해 **`train.jsonl`만** 교체하고
`validation.jsonl`·`val-real.jsonl`·`symbols.json`·`audio/`는 **바이트 그대로** 두었다(측정 40문장과 학습 중 감시 클립이 완전히 동일해진다).
`prepare`는 다시 돌리지 않았다 — 걸러낸 manifest로 재준비하면 검증 split의 크기·구성과 오디오 파일명이 함께 바뀌어 한 축 조작이 아니게 된다
(`prepare.py:157-189`, `:79-85`). 추출은 **하위 코퍼스 일곱 개 접두 일치로 층화 + 비례·큰-나머지 배분 + `random.Random(20260909)` 한 스트림**으로

고유 음소 문자 **36 → 33**(빠진 `!`·`?`·`ʷ`가 **측정 40문장에 하나도 없음**). `inflect-adapt audit --strict` **통과**.

무결성은 범용 검사의 임계가 아니라 **엄격 검사**(`exact_match.py --dataset-axis train`)로 잡았고 전부 통과했다: 두 `training-options.json`
